# Feature Specification: 모바일·태블릿 반응형 UI 및 PWA 전환

**Feature Branch**: `feat/responsive-ui`

**Created**: 2026-07-14

**Status**: Draft

**Input**: User description: "이제 모바일, 태블릿 사이즈에서도UI가 예쁘게 나오게 하고싶어. 데스크톱 사이즈가 아니라 PWA로 모바일 태블릿도 예쁘게 구며야할거같아. 이부분에 대한 spec명세서 작성해줘봐"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 모바일 화면에서 핵심 화면이 깨지지 않고 예쁘게 보인다 (Priority: P1)

스마트폰으로 서비스에 접속한 사용자가 랜딩 페이지부터 서비스 선택, 채팅/상담, 궁합 결과, 마이페이지 등 핵심 화면을 이용할 때, 데스크톱 전용으로 설계된 레이아웃이 잘리거나 겹치거나 가로 스크롤이 생기지 않고, 손가락으로 편하게 조작할 수 있는 크기와 간격으로 표시된다.

**Why this priority**: 현재 UI는 데스크톱 최소 너비(1024px)를 기준으로 설계되어 있어, 모바일 사용자가 서비스를 정상적으로 이용하지 못할 가능성이 가장 크다. 모바일 접근성 확보가 없으면 이후 태블릿 대응이나 PWA 설치 기능은 의미가 없다.

**Independent Test**: 실제 스마트폰 또는 360px~767px 너비의 브라우저 뷰포트로 각 페이지(`/`, `/select`, `/chat`, `/career-timing`, `/compatibility`, `/compatibility/result`, `/consultation`, `/my-page`)에 접속해, 가로 스크롤 없이 모든 콘텐츠와 버튼을 확인·조작할 수 있는지로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 사용자가 너비 360px~767px의 모바일 기기로 랜딩 페이지에 접속했을 때, **When** 페이지가 로드되면, **Then** 모든 텍스트와 버튼이 가로 스크롤 없이 화면 안에 보이고 글자가 잘리지 않는다.
2. **Given** 사용자가 모바일 화면에서 서비스 선택 화면을 보고 있을 때, **When** 사용자가 서비스 카드를 터치하면, **Then** 오탭 없이 의도한 항목이 정확히 선택된다.
3. **Given** 사용자가 모바일 화면에서 채팅/상담 화면을 이용 중일 때, **When** 화면 하단 입력창에 텍스트를 입력하면, **Then** 가상 키보드가 올라와도 입력창과 전송 버튼이 가려지지 않는다.
4. **Given** 사용자가 모바일 화면에서 버튼이 여러 개 함께 배치된 화면(예: 모달 하단 버튼 그룹, 화면 하단 액션 버튼)을 볼 때, **When** 화면을 확인하면, **Then** 각 버튼이 서로 겹치지 않고 텍스트가 잘리지 않은 채 개별적으로 구분되어 터치할 수 있다.

---

### User Story 2 - 태블릿 화면에서 여백을 활용한 레이아웃이 제공된다 (Priority: P2)

태블릿으로 접속한 사용자가 모바일 레이아웃을 단순히 확대한 형태가 아니라, 태블릿의 넓은 화면을 활용해 정보 밀도와 여백이 적절히 조정된 화면을 이용한다.

**Why this priority**: 태블릿은 모바일과 데스크톱의 중간 사용성을 가지므로 모바일 대응(P1)이 끝난 뒤에 다뤄야 하지만, 서비스의 주요 잠재 사용자층(가로 모드 태블릿 이용 등)을 위해 데스크톱 대응 다음으로 중요하다.

**Independent Test**: 768px~1023px 너비의 뷰포트(세로/가로 모드 모두)로 핵심 화면에 접속해, 모바일 레이아웃의 단순 확대가 아닌 태블릿에 맞는 레이아웃(예: 2단 배치, 조정된 여백)이 적용되는지로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 사용자가 768px~1023px 너비의 태블릿으로 서비스 선택 화면에 접속했을 때, **When** 화면을 확인하면, **Then** 모바일처럼 1열로 늘어선 카드가 아니라 태블릿 너비에 맞는 배치로 표시된다.
2. **Given** 사용자가 태블릿을 가로로 회전했을 때, **When** 화면 방향이 바뀌면, **Then** 레이아웃이 깨지지 않고 새로운 너비에 맞게 자연스럽게 재배치된다.
3. **Given** 사용자가 모바일 화면(예: 375px)과 태블릿 화면(예: 820px)에서 같은 화면을 각각 볼 때, **When** 버튼이나 카드 같은 UI 요소를 비교하면, **Then** 두 화면의 요소 크기가 화면 폭에 비례해 연속적으로 커진 것이 아니라, 각 구간에 맞게 별도로 구성된 배치와 크기로 보인다.

---

### User Story 3 - 앱처럼 설치하고 실행할 수 있다 (Priority: P3)

모바일/태블릿 사용자가 브라우저에서 서비스를 홈 화면에 설치하고, 설치된 아이콘을 통해 브라우저 주소창 없이 독립 실행형 앱처럼 서비스를 이용한다.

**Why this priority**: 반응형 레이아웃(P1, P2)이 갖춰진 뒤에야 "앱처럼 예쁘게 보이는" PWA 설치 경험이 의미를 가지므로 세 번째 우선순위로 둔다.

**Independent Test**: 지원 브라우저(모바일 Chrome, iOS Safari)에서 서비스에 접속해 "홈 화면에 추가" 기능으로 설치하고, 설치된 아이콘 실행 시 주소창 없는 전체 화면 형태로 열리는지로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 사용자가 지원 브라우저로 서비스에 접속했을 때, **When** 브라우저의 설치 기능(또는 설치 안내)을 사용하면, **Then** 앱 이름과 아이콘이 지정된 형태로 홈 화면에 추가된다.
2. **Given** 사용자가 홈 화면에 설치된 아이콘을 실행했을 때, **When** 앱이 열리면, **Then** 브라우저 주소창/탭 UI 없이 독립 실행형 화면으로 표시된다.
3. **Given** 설치된 앱을 실행 중일 때, **When** 기기 화면 상단에 노치나 상태 표시줄이 있으면, **Then** 콘텐츠가 해당 영역에 가려지지 않는다.

---

### Edge Cases

- 320px~359px처럼 지원 최소 너비(360px)보다 좁은 초소형 화면에서는 어떻게 표시되는가?
- 사용자가 브라우저 창 크기를 실시간으로 조절하거나 기기를 회전할 때 레이아웃이 즉시, 깨짐 없이 재조정되는가?
- 네트워크 연결이 끊긴 상태에서 설치된 앱을 실행하면 어떤 화면이 표시되는가? (오프라인 지원은 범위 외이므로, 일반 웹처럼 연결 실패를 알리는 기본 브라우저/네트워크 에러 화면이 표시되는 것을 허용한다.)
- 폴더블 기기처럼 화면 비율이 극단적인 경우(매우 좁고 긴 화면) 핵심 콘텐츠가 잘리지 않는가?
- 기존 데스크톱(1024px 이상) 사용자에게는 현재와 동일한 레이아웃과 동작이 유지되는가(회귀 없음)?
- iOS Safari와 Android Chrome처럼 설치 방식이 다른 브라우저에서 각각 설치 안내가 올바르게 동작하는가?
- 뷰포트 너비가 구간 경계(예: 767px→768px)를 넘나들 때, 버튼 등 UI 요소 크기가 서서히 늘어나는 대신 각 구간에 정의된 구성으로 즉시 전환되는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 너비 360px~767px 모바일 뷰포트에서 서비스 내 모든 화면(랜딩, 서비스 선택, 채팅/상담, 커리어 타이밍, 궁합, 궁합 결과, 마이페이지, 인증 모달, 에러/404 화면 포함)이 가로 스크롤이나 요소 겹침 없이 표시되어야 한다.
- **FR-002**: 시스템은 너비 768px~1023px 태블릿 뷰포트에서 모바일 레이아웃을 단순 확대하지 않고, 화면 너비를 활용한 레이아웃(예: 다단 배치, 조정된 여백)을 제공해야 한다.
- **FR-003**: 시스템은 터치로 조작하는 모든 버튼·링크·입력 요소에 대해 최소 44x44px의 터치 영역을 확보해야 한다.
- **FR-004**: 시스템은 화면 크기(모바일/태블릿/데스크톱)에 따라 폰트 크기, 여백, 컴포넌트 크기를 적절히 조정해 텍스트가 잘리거나 겹치지 않아야 한다.
- **FR-005**: 시스템은 기기 회전(세로↔가로) 및 브라우저 창 크기 변경 시 레이아웃이 깨짐 없이 즉시 재배치되어야 한다.
- **FR-006**: 시스템은 기존 데스크톱(1024px 이상) 화면의 레이아웃과 동작을 이번 변경으로 인해 저하시키지 않아야 한다.
- **FR-007**: 시스템은 앱 이름, 아이콘, 테마 색상, 시작 화면, 실행 모드를 정의하는 PWA 설치 메타데이터(매니페스트)를 제공해야 한다.
- **FR-008**: 사용자는 지원 브라우저(모바일 Chrome, iOS Safari 등)에서 서비스를 홈 화면에 설치할 수 있어야 한다.
- **FR-009**: 설치된 앱은 브라우저 주소창·탭 UI 없이 독립 실행형(standalone) 화면으로 실행되어야 한다.
- **FR-010**: 시스템은 노치, 상태 표시줄 등 기기의 세이프 영역(safe area)을 침범하지 않도록 콘텐츠 레이아웃을 조정해야 한다.
- **FR-011**: 시스템은 FR-001에 나열된 핵심 서비스 화면뿐 아니라, 인증 모달, 에러/404 화면 등 사용자가 마주칠 수 있는 서비스 내 모든 화면에 대해서도 모바일·태블릿 뷰포트에서 가로 스크롤이나 요소 겹침 없이 표시되어야 한다.
- **FR-012**: 시스템은 설치 가능성(FR-007~FR-009)과 독립 실행형 화면 제공(FR-009), 세이프 영역 대응(FR-010) 수준까지 PWA 요건을 충족하면 되며, 네트워크 연결이 끊긴 상태에서의 오프라인 콘텐츠 제공은 이번 범위에 포함하지 않는다.
- **FR-013**: 시스템은 버튼, 카드 등 UI 요소의 크기와 배치를 화면 폭에 비례하여 연속적으로 늘리거나 줄이는 유동적 스케일링 방식이 아니라, 모바일·태블릿·데스크톱 각 구간마다 별도로 설계된 고정 구성(레이아웃, 요소 크기, 정렬)을 적용해야 한다.
- **FR-014**: 시스템은 뷰포트 너비가 구간 경계를 넘어갈 때 레이아웃이 점진적으로 변형되지 않고, 해당 구간에 정의된 구성으로 전환되어야 한다.
- **FR-015**: 시스템은 모바일·태블릿 뷰포트에서 버튼이 다른 버튼이나 텍스트·이미지 등 다른 UI 요소와 서로 겹치지 않아야 하며, 여러 버튼이 함께 배치되는 경우(예: 모달 하단 버튼 그룹, 화면 하단 액션 버튼)에도 각 버튼이 잘리거나 겹치지 않고 개별적으로 인식·조작 가능해야 한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 모바일(360px~767px)과 태블릿(768px~1023px) 각 대표 해상도에서, 정의된 모든 핵심 화면에 가로 스크롤이 0건 발생한다.
- **SC-002**: 모바일 사용자가 핵심 이용 흐름(랜딩 → 서비스 선택 → 상담/궁합 시작)을 완료하는 데 걸리는 조작 횟수와 소요 시간이 데스크톱 사용자 대비 10% 이내로 유지된다.
- **SC-003**: 지원 브라우저 사용자는 3회 이하의 조작(설치 버튼/메뉴 진입 포함)으로 서비스를 홈 화면에 설치할 수 있다.
- **SC-004**: 설치된 앱을 홈 화면 아이콘으로 실행하면 100% 브라우저 주소창 없는 독립 실행형 화면으로 열린다.
- **SC-005**: 모바일/태블릿 사용자 대상 사용성 테스트에서 90% 이상이 화면 레이아웃과 터치 조작에 대해 "불편함 없음"으로 응답한다.
- **SC-006**: 정의된 화면 구간(모바일/태블릿/데스크톱) 내에서는 뷰포트 폭을 변경해도 버튼 등 주요 UI 요소의 크기가 변하지 않고, 구간 경계를 넘는 순간에만 다른 구성으로 전환된다.
- **SC-007**: 모바일과 태블릿 대표 해상도에서 전수 검사한 모든 화면 중 버튼이 다른 버튼 또는 다른 UI 요소와 겹치는 사례가 0건이다.

## Assumptions

- 태블릿 기준 너비는 768px~1023px로, 1024px 이상은 기존 데스크톱 레이아웃 기준을 그대로 유지한다(현재 Tailwind 설정의 breakpoint와 일치).
- 지원 브라우저는 표준 PWA 설치 기능을 제공하는 최신 모바일 Chrome, iOS Safari 등으로 가정하며, 구형/비표준 브라우저에 대한 별도 폴백은 이번 범위에 포함하지 않는다.
- 다국어(영어 등) 대응은 이번 기능 범위에 포함하지 않으며, 기존 한국어 UI 콘텐츠를 그대로 유지한다.
- 푸시 알림 기능은 이번 PWA 전환 범위에 포함하지 않는다.
- 오프라인 상태에서의 콘텐츠 제공(서비스 워커 캐싱을 통한 앱 셸/이전 방문 데이터 표시)은 이번 범위에 포함하지 않으며, 네트워크가 끊기면 일반 웹과 동일하게 동작한다.
- 반응형 대응 범위는 핵심 서비스 화면뿐 아니라 인증 모달, 에러/404 화면 등 서비스 내 모든 화면을 포함한다(관리자 전용 화면은 존재하지 않는 것으로 확인됨).
- 최소 지원 뷰포트 너비는 360px이며, 그보다 좁은 화면에 대한 정밀 최적화는 이번 범위에 포함하지 않는다(단, 콘텐츠가 완전히 깨지지는 않아야 한다).
- 기존 사용자 인증, 데이터, API 로직에는 변경이 없으며, 이번 기능은 화면 레이아웃/스타일과 PWA 설치 메타데이터에 한정된다.
- 구간별 레이아웃(FR-013, FR-014)은 Flexbox 기반 배치를 사용해 구현하는 것을 전제로 하며, 요소 크기를 화면 폭에 비례해 계산하는 유동적(fluid/percentage) 크기 조정 방식은 사용하지 않는다.
